# acceptance.md — 合格条件（完成条件）

> 書き換えてよいのは人間だけ。AI がゆるめたり消したりしてはいけない。
> 「完成しました」という発言は証拠にならない。下の「証拠」欄にあるものだけで判定する。
> 証拠は `evals/evidence/<タスクID>/` に保存する。

## 共通条件（すべてのタスク）
| ID | 条件 | 証拠 | 確かめ方 |
|---|---|---|---|
| AC-00a | 既存のテストがすべて通る | `pytest.log` | 評価役が `pytest -q` を再実行し、失敗0件 |
| AC-00b | フロントエンドがビルドできる（フロントを触ったタスクのみ） | `build.log` | `npm run build` が成功 |
| AC-00c | 秘密情報が含まれていない | `secret-scan.log` | `docs/safety.md` 3章のコマンドで何も出ない |
| AC-00d | tasks.json のルール違反がない | `check_tasks.log` | `python evals/check_tasks.py` がエラー0件 |

## タスク別の条件
| ID | 条件 | 証拠 | 確かめ方 |
|---|---|---|---|
| AC-01 | 作業ブランチがあり、ハーネス一式がコミットされている | `git.log` | `git log --oneline -3` と `git branch --show-current` |
| AC-02 | 未確定事項 Q1〜Q3 に人間の回答が記録されている | `docs/requirements.md` の5章 | 人間の回答が書かれている（AI の推測ではない） |
| AC-03 | pytest で自動テストが動き、既存機能のテストが5件以上ある | `pytest.log` | 件数と、テスト名が既存機能に対応していること |
| AC-04 | 外部 API を呼ばずにテストが通る | `pytest.log`、テストコード | ネットワーク無しでも通る（モック使用がコードで確認できる） |
| AC-05 | 観点・Question・採点結果の型があり、おかしな入力をはじく | テストコード、`pytest.log` | 配点0、名前が空、観点16個、段階が5個でない、ID重複 → それぞれエラーになるテストがある |
| AC-06 | 観点→Question 生成が、観点1つにつき Question 1つ、`criterion_id` 一致、5段階を満たす | テストコード、`pytest.log` | モック Claude の出力が欠けている/余分なときにエラーになるテストもある |
| AC-07 | Jev 採点が正しい形で呼ばれ、配点換算がサーバーの計算で行われる | テストコード、`pytest.log` | モック Jev に渡した `state` が書き起こし文、`questions` が Score 型。換算例: score 3.0, 5段階, 配点20 → 15.0 |
| AC-08 | 音声 → 文字起こし → Jev 入力 がつながっている。空の書き起こしはエラー | テストコード、`pytest.log` | モック Whisper の出力が Jev の `state` にそのまま入るテスト |
| AC-09 | API が仕様どおりに応答する（成功・入力ミス・キー未設定） | `pytest.log`（TestClient 使用） | 成功200、不正な観点400、キー未設定で日本語エラー |
| AC-10 | Questions を保存・一覧・読み込みできる | テストコード、`pytest.log` | 保存→一覧→読み込みで同じ内容に戻る |
| AC-11 | 画面で観点を入力し、生成された Questions を確認・編集できる | `screenshot-*.png`、`build.log` | スクショに入力欄・生成結果・編集欄が写っている |
| AC-12 | 画面で音声を送ると、観点別の点数・合計・確信度の注意が表示される | `screenshot-*.png`、`build.log` | モック or 実 API の結果がスクショで確認できる |
| AC-13 | 実 API で1回通しで動く（人間承認済み） | `e2e.log`、`screenshot-*.png`、`progress.md` の承認記録 | ログに観点数と同数の点数、合計点がある。キーや個人情報がログに無い |
| AC-14 | README に新機能の使い方と必要なキーが書かれている | `README.md` の差分 | 初心者が手順どおりに起動できる内容か、評価役が手順を読んで確認 |
