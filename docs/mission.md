# mission.md — 何を、誰のために作るか

> 書き換えてよいのは人間だけ。AIは変更案を `progress.md` の「提案」に書く。

## 最終的な完成品
harinezumi に **「コンテスト観点モード」** を追加する。

1. ユーザーが、出場するピッチコンテストの **採点観点**（例:「課題の明確さ 20点：…」）を入力する。
2. AI（Claude）が各観点を **Jev（TypeSafe AI）の Score 型 Question** に変換する。
   - Question = Jev に「何を」「どんな段階で」採点させるかを伝える、型の決まった質問。
3. ユーザーは生成された Questions を画面で確認・修正できる（人間が最終決定する）。
4. ユーザーが発表の **音声（または動画）** をアップロードすると、Whisper が **文字起こし** する。
5. 文字起こしテキストを Jev に渡し、観点ごとの点数と確信度を受け取る。
6. サーバーが点数をコンテストの配点に **計算で** 換算し、合計点と一緒に画面に表示する。
7. 一度作った Questions は保存して、同じコンテストで何度でも使い回せる。

## 対象者
- **アプリの利用者**: 学生ビジネスコンテスト等に出場する人と、その指導者。
  コンテストごとに採点基準が違うので、「本番の基準で」事前に練習採点したい。
- **このハーネスの利用者**: AI 初心者の開発者（このリポジトリの持ち主）。
  AI に作業を任せ、途中で会話が切れても続きから再開したい。

## やらないこと（スコープ外）
- 本番サーバー（Vercel など）への公開。 ※ 公開は人間の承認が必要な別の仕事
- ログイン機能・データベース
- 既存の「通常審査モード」の採点方法の変更
- 長い音声の自動分割（Whisper の 25MB 上限はそのまま）

## 成功の姿
同じ音声・同じ Questions なら、毎回ほぼ同じ点数になり、
どの観点で何点だったか・どれくらい確信があるかが、初心者にも読める形で表示される。
