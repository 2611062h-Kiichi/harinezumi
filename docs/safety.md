# safety.md — 安全ルール

> 書き換えてよいのは人間だけ。迷ったら「やらずに聞く」。

## 1. 人間の承認が必要な操作（実行前に必ず聞く）
| 操作 | このプロジェクトでの具体例 |
|---|---|
| メールや DM の送信 | 結果を誰かに送る処理を動かす |
| SNS への投稿 | — |
| 購入や決済 | 有料プランへの変更、**実際の API（Anthropic / OpenAI / TypeSafe）を呼ぶテスト**（1回ごとに料金がかかる） |
| データの削除 | `backend/data/` の中身の削除、ファイル・ブランチの削除 |
| 本番環境への反映 | Vercel などへのデプロイ、`main` へのマージ、`git push` |
| 権限の変更 | GitHub の設定、`.claude/settings.json` の permissions 変更 |
| 顧客への連絡 | — |
| 法的な同意 | 外部サービスの利用規約への同意、新しい外部サービスの登録 |
| その他 | 新しい **外部サービス** やライブラリの追加（テスト用の pytest などを除く）、`git reset --hard` |

承認の取り方: 「何を・なぜ・失敗したらどうなるか」を1〜3行で書いてユーザーに聞き、**明確な「はい」** をもらってから実行する。
1回の承認は、その1回の操作にだけ有効。

## 2. 絶対にしてはいけない操作
- APIキー・パスワード・秘密情報を、指示ファイル・コード・ログ・証拠ファイル・コミットメッセージに書く
- `backend/.env` を読む・表示する・コミットする
- `tasks.json` のタスクを削除する、`task` / `dependencies` / `acceptance` を書き換える
- `evals/acceptance.md`（合格条件）を書き換える
- 証拠なしで `passes: true` にする。テストを消したり無効化したりして合格にする
- `git push --force`、`main` への直接コミット
- 実際の利用者の音声・個人情報を `evals/evidence/` やリポジトリに保存する

## 3. 秘密情報の扱い
- キーは `backend/.env` にだけ置く（`.gitignore` 済み）。見本は `backend/.env.example`（ダミー値のみ）。
- キーがあるかどうかは「設定されているか（True/False）」だけ確認する。値は表示しない。
- コミット前に確認: `git diff --cached | grep -nE "sk-|ts-[A-Za-z0-9]{8,}|api_key\s*=\s*['\"][^'\"]+"` で何も出ないこと。

## 4. 失敗したときの戻し方
1. **止まる**: 同じ失敗を3回繰り返したら作業をやめ、`progress.md` の「要確認」に状況を書いてユーザーに聞く。
2. **コミット前の失敗**: `git diff` で変更を確認し、そのタスクで変えたファイルだけ `git restore <ファイル>` で戻す。
3. **コミット後の失敗**: `git revert <コミットID>`（履歴を消さずに打ち消す）。`reset --hard` は承認が必要。
4. **タスクの状態**: `tasks.json` のそのタスクを `status: "todo"`、`passes: false` に戻し、理由を `progress.md` に書く。
5. **依存パッケージが壊れた**: `backend/.venv` を作り直す（`python -m venv .venv` → `pip install -r requirements.txt`）。
